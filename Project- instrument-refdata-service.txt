## Explanation of Each Package

 1. config/

* Holds Spring Boot configuration beans
* Examples:

  * `SecurityConfig.java` → Spring Security setup
  * `KafkaConfig.java` → Kafka producer/consumer beans
  * `AuditingConfig.java` → JPA Auditing (`@EnableJpaAuditing`)
  * `OpenAPIConfig.java` → Swagger setup
* These are loaded automatically by Spring Boot because they’re annotated with `@Configuration`.

---

 2. controller/

* Holds REST API endpoints.
* Example: `InstrumentController.java` with methods like:

  ```java
  @GetMapping("/api/v1/instruments/{id}")
  public ResponseEntity<InstrumentDto> getById(@PathVariable UUID id) { ... }
  ```
* Annotated with `@RestController`.
* Should only handle HTTP layer logic: validation, request mapping, calling services.
* No DB or business logic here.

---

 3. dto/

* DTO = Data Transfer Object.
* Purpose: keep your API layer clean and separate from DB layer.
* Example:

  ```java
  public record InstrumentDto(UUID id, String isin, String ticker, String exchange, String currency) {}
  ```
* Use `@Valid` annotations here for input validation.

---

 4. entity/

* Contains JPA entities (database tables).
* Example:

  ```java
  @Entity
  public class Instrument { ... }
  ```
* Mapped with Hibernate annotations (`@Entity`, `@Column`, `@Id`).
* Represent the persistence model, not directly exposed to clients.

---

 5. exception/

* Central place for exceptions and global error handling.
* Example:

  * `InstrumentNotFoundException.java`
  * `GlobalExceptionHandler.java` with `@ControllerAdvice` → returns Problem JSON (RFC 7807).

---

 6. mapper/

* Converts Entity ↔ DTO.
* Industry uses MapStruct (`@Mapper(componentModel = "spring")`).
* Example: `InstrumentMapper.java` → maps `Instrument` → `InstrumentDto`.

---

 7. repository/

* Contains Spring Data JPA repositories.
* Example:

  ```java
  public interface InstrumentRepository extends JpaRepository<Instrument, UUID>, JpaSpecificationExecutor<Instrument> {}
  ```
* Responsible only for database queries.
* No business logic here.

---

 8. service/

* Contains business logic.
* Example:

  * `InstrumentService.java` (CRUD operations, CSV ingestion, publishing events).
* Annotated with `@Service`.
* This is where transactions (`@Transactional`) are managed.
* Services call repositories, perform validations, publish events, etc.

---

 9. util/

* Contains helper classes.
* Example:

  * `ISINValidator.java` → validate ISIN format.
* Keeps reusable utility code separate from services.

---

 10. events/

* Handles domain events and Kafka publishing.
* Example:

  * `InstrumentUpdatedEvent.java` (POJO event object).
  * `KafkaPublisher.java` (sends event to Kafka topic).
* Keeps eventing concerns separated from business logic.

---

 11. resources/db/migration/

* Stores Flyway DB migration scripts (`V1__init.sql`, `V2__add_indexes.sql`, etc.).
* Ensures schema is version-controlled and portable.
* Flyway runs them automatically on app startup.

---

 12. test/

* unit/ → pure Java tests (mappers, validators, services with mocks).
* integration/ → database + Kafka tests using Testcontainers.
* Mirrors `main/java` package structure.

---
